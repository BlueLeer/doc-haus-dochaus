# 重庆劳动争议平台改造计划

日期：2026-09-05  
状态：规划完成，业务改造尚未开始。本文是实施基线；法律条文、地方标准和金额参数需在内容建设阶段核验，本文不提供法律适用结论。

## 1. 产品目标与首版范围

将 doc.haus 改造为中国大陆劳动争议办案辅助平台，首个上线地区为重庆，后续通过地区包上线其他地区。沿用 OpenCode 引擎、事项隔离、文档解析、BGE-M3 检索、引用验证、Word 输出、技能与工作流设计。

首版默认面向律师，支持劳动者侧和用人单位侧，由每个案件明确选择。中文为主，保留已有语言切换。工作路径为：建立案件 → 上传材料 → 确认事实 → 梳理请求与证据 → 核验规则 → 计算金额 → 起草文书 → 复核。

首版分批覆盖：

- 第一批：劳动关系确认、解除/终止争议、经济补偿与赔偿、工资及奖金争议。
- 第二批：加班费、未签书面劳动合同二倍工资、未休年休假工资、竞业限制。
- 暂缓完整支持：工伤待遇、社保经办程序、人事争议、涉外及复杂跨区域用工。涉及这些事项时保留材料分析能力并指出未覆盖部分，不生成未经验证的计算或程序结论。

首版地区选择只开放重庆。默认地区用于初始化和检索提示，不能据此认定所有争点均适用重庆规则；实际工作地、单位所在地、受理地不同的案件需逐项确认。

## 3. 架构约定

### 地区与规则

- 全国包 `CN`；重庆包 `CN-CQ`，显式声明父级 `CN`。
- 地区注册表管理父级、上线状态和可用来源；解析器负责父级展开和去重。
- 地区规则作为按需检索的数据，提示词只放适用方法和检索约束，不注入整套法规。
- 后续地区通过相同数据格式和服务接口接入。禁止在智能体和计算器中散落重庆名称判断。
- 多个规则共同适用或出现冲突时，展示来源、效力类型及待判断问题，不能简单设定“地方覆盖全国”。

### 事实、规则与计算分离

案件事实独立于聊天记录保存，每项重要事实包含值、原文引用及“待确认/已确认/存在争议”状态。保留不同说法，不让模型静默覆盖已确认事实。

规则记录至少包含：稳定 ID、版本 ID、地域、主题、文件名称、文号、发布机关、效力类型、公布及施行日期、失效或修改信息、原文条款、来源 URL、获取时间、核验状态、关联旧版本及过渡条款。未知字段保持未知，不能由模型猜测。

计算使用确定性函数和十进制金额或整数分；模型负责识别事实和候选规则。结果记录输入事实、公式版本、地区参数版本、舍入方式及来源。缺少条件时返回待补信息或明确标注的情景计算，不给出貌似确定的总额。

### 存储及数据边界

- 继续使用现有事项和数据库基础，新增内容在 ingest 服务及法律配置层实现，首版不新增独立微服务。
- 案件证据库和共享法律资料库逻辑隔离；案件文档引用校验不能自动等同于法规有效性核验。
- 系统内置内容、用户自建内容、上传证据、下载缓存分别识别。清理不触碰用户证据、密钥和既有嵌入缓存。
- 既有案件维持原 ID、目录与会话。旧辖区绑定保留迁移记录；不自动把旧案件适用法改成重庆。

### 智能体与技能

首版采用少量角色：劳动争议主助手、法规研究助手、文书起草助手和复核子智能体。案件受理、请求分析、证据与程序审查先通过技能组合；确定性计算通过工具调用。后续根据评测结果再拆分角色。

技能按全国基础、程序、解除、报酬、证据、计算解释、地方规则查询拆分。地区标准放规则库，技能引用查询工具。保留管理员维护模板、技能和工作流的能力；初期只调整导航，不能将隐藏页面宣称为真实权限控制。

## 4. 清理和保留清单

| 类别 | 拟处理 |
| --- | --- |
| 欧美及其他非目标辖区包 | 完成依赖核对和备份后，从运行目录删除 |
| 美国 NDA、SaaS、服务协议、英格兰委托书、GDPR 指引 | 移出运行目录；中国劳动文书另建，不翻译后直接套用 |
| CourtListener、美国 case-law 接入 | 检查配置、调用方和依赖后退出运行版本 |
| 美国引用规则和商业条款市场基准 | 移除或替换；保留文档原文引用与校验机制 |
| 问答、起草、审查与复核 | 改造为劳动争议角色，更新自动路由及工具权限 |
| 比较、义务提取、脱敏、Word 修订 | 复用底层能力，按办案需要决定是否独立展示 |
| 模板/技能/工作流构建器 | 保留维护能力，检查其生成内容是否仍带欧美假设 |
| 演示材料和测试 | 用合成重庆劳动争议样本替换系统演示数据，保留通用引擎测试 |
| 用户创建的智能体、技能、模板、工作流 | 根据注册表识别，保留内容；迁移不适配绑定，不混同于系统包删除 |

备份存放于引擎扫描范围以外，并记录文件清单和校验值。备份范围覆盖待删资产、配置和待迁移元数据；限制对密钥文件的额外复制。恢复演练通过后才执行物理删除。

## 5. 实施阶段与验收

### P0：建立基线与清理依赖

任务：核对启动方式、运行环境、WORKSPACE_ROOT 数据位置（不输出密钥）；建立可恢复快照；枚举内置/自建资产；查明所有技能发现路径、MCP、注册表、提示词及工具调用；记录当前启动、上传、引用、文书输出基线。

交付：资产依赖表、逐项删除/替换清单、恢复说明、已知问题清单。

验收：选定备份文件恢复校验成功；系统内容和用户内容区分清楚；核心流程基线可复现。

### P1：重庆产品骨架与运行时裁剪

状态：已完成（2026-09-05）。

任务：建立地区注册与父级解析；增加 `CN`/`CN-CQ` 框架；同步服务端发现、引擎配置、技能访问权限、前端列表和自动路由；替换默认演示流程；完成无用包删除；界面“事项”调整为“案件”。

交付：重庆产品可启动，活跃资产清单可检查；规则内容尚未核验时明确显示未就绪。

验收：仅开放重庆；父级正确加载；新会话不能访问已移除包；旧案件及自建资产可访问；不存在未解析的智能体/技能调用。地区启用清单必须由实际加载器消费，不能仅增加文件。

### P2：结构化案件与证据工作台

状态：已完成（2026-09-05）。实现与回归记录见 [P2 验收记录](p2-verification.md)。

任务：添加客户立场、争议阶段、主体、地点、入职与离职、送达及程序日期、工资结构；建立带证据引用的事实时间轴、请求与证据矩阵；支持用户确认和修正。

交付：从材料生成可编辑案件概况、时间轴和证据缺口表。

验收：事实可追溯到文档；争议事实分别保留；修改已确认输入后相关分析显示待更新；旧案件兼容读取。

### P3：全国与重庆规则资料

任务：从官方来源整理首批争点的法律、司法解释、地方规定及地方标准；建立版本及效力元数据；实现法律资料独立检索和规则查询工具；核对网站访问方式和使用条件。可用网页读取、经核验本地资料导入均可作为首版来源，不能承诺未验证的案例库 API。

交付：带来源和核验记录的首批规则集、官方来源列表、版本查询接口。

验收：能按相关日期查询历史版本；过渡条款可展示；旧版法规不会作为当前规则无提示输出；法规、地方口径、案例与推断分别标识；来源不足时列明缺口。

### P4：第一批专业分析、计算与文书闭环

任务：落地首批请求分析技能；实现已核验范围的计算函数；输出请求、要件、事实、证据、抗辩和金额；增加仲裁申请书、答辩书、证据目录、案件分析报告模板；复核引用、金额及文书与确认事实的一致性。

交付：第一批案由可从上传材料完成分析和 Word 草稿。

验收：每项法律结论有可核验依据；金额可复算；缺少输入不会擅自补齐；文书不把模型推断写成当事人确认事实；生成后读回核对。

### P5：扩充案由并验证地区扩展

任务：按相同接口完成第二批案由；使用匿名或合成测试材料覆盖工资期间、时效、证据冲突、来源失效、未知地点；用未上线的合成第二地区包验证架构，不将测试参数放入生产数据。

交付：重庆首版验收报告、地区接入指南、回滚说明及未覆盖事项清单。

验收：增加测试地区无需复制智能体或修改计算核心；前后端及引擎可用地区一致；用户数据迁移可回滚；首版所有承诺案由均有测试样本。

依赖顺序：P0 → P1 → P2；P3 的内容整理可与 P2 独立推进；P2 + P3 完成后进入 P4；最后 P5。先交付第一批完整闭环，再扩充第二批。

## 6. 验证方法

- 单元测试：地区继承、按日期选取版本、事实确认状态和金额计算，使用独立人工核算结果。
- 集成测试：真实配置加载、技能禁用、自动路由、旧事项读取和迁移恢复。
- 端到端：上传 DOCX/PDF → 查看状态 → 校验引用 → 分析 → 生成并读回 Word。
- 法律内容验收：逐条记录来源、版本和适用条件，项目负责人/法律审核人完成实务核验后才标记生产可用。
- 在各包目录运行检查，补齐 web 类型检查脚本；运行相关 ingest/dochaus 测试及 web 构建，不以 Vite 构建冒充类型检查。

## 7. 估算与待确认事项

工程规模暂评中等，规则与实务验收规模中高。精确工期在 P0 后按资产依赖、来源可访问性和样本情况估算，不把提示词编写时间当成完整产品工期。

暂按以下产品选择推进后续设计：面向律师；支持双方立场；重庆首先上线；四类首批争议先完成闭环；保留维护界面；不在首版新建账号权限系统。

会影响后续范围、但不阻碍 P0 的信息：用户主要代理哪一方；最常见的两类争议；是否有可脱敏的样本案卷及现用文书模板；已有重庆规则资料的来源和版本情况。
