# P2 实现与回归记录

日期：2026-09-05

## 交付范围

- 案件内新增“案件工作台”，包含案件概况、事实时间轴、证据目录、请求与证据矩阵和分析记录。
- 概况支持委托立场、争议阶段、劳动者/单位、工作地/单位所在地/合同履行地、入离职、送达及程序日期、工资结构，并细分基本工资、绩效、奖金、补贴、支付周期和实发期间。
- 每条记录保存立场、确认状态、原文来源和证据缺口。劳动者与单位的不同说法可以并列，不合并为确定事实。
- “从材料整理”进入劳动争议助手并预填整理请求，发送后助手读取文档，向工作台追加待确认草稿。人工输入可直接编辑保存。
- 服务端逐字验证 DOCX/PDF 引文，记录文件指纹。文档变更或删除后标记来源待复核。
- 案件保存采用版本冲突检查和原子写入；修改后既有分析保留原版本并显示待更新。
- 所有案件智能体获得当前工作台数据与来源状态。助手只可追加提取草稿，不覆盖人工确认的已有记录。
- 旧案件无 casebook.json 时返回空工作台，保留旧 matter.json、文档和会话。

## 文件与接口

共享字段与类型：`dochaus/lib/casebook-model.ts`。

持久化：`services/ingest/src/casebook.ts`，数据保存在案件目录 `.dochaus/casebook.json`。

接口：`GET /matters/:id/casebook`，`POST /matters/:id/casebook`（replace/propose/analysis）。

智能体工具：`dochaus/tool/casebook.ts`；当前案件上下文由 `dochaus/plugin/legal.ts` 注入。

页面：`apps/web/src/components/CaseWorkbench.tsx`。

## 复现

在 `services/ingest` 运行 `bun test` 和 `bun run typecheck`；在 `dochaus/lib` 运行 `bun test`；在 `apps/web` 运行 `bun run typecheck` 和 `bun run build`。

启动三项本地服务后，在 `services/ingest` 运行：

```sh
bun scripts/p2-smoke.ts
```

该命令只创建并删除本次虚构测试案件。加 `--keep` 可保留，用输出的案件ID运行真实模型回归（会使用当前配置模型）：

```sh
bun scripts/p2-agent-smoke.ts <虚构测试案件ID>
bun scripts/p2-review-smoke.ts <虚构测试案件ID>
```

已保留供界面验收的虚构案件：`p2-71db6f`，标题“P2回归验收（虚构材料）”。不包含真实当事人材料。

## 阶段边界

本阶段记录案情、材料和分析版本；全国/重庆规则库仍待 P3，法定金额计算和专用文书闭环仍待 P4。模型提取必须经承办人核对。当前以案件整体版本失效分析，尚未按单个字段精细追踪依赖。

回退页面和工具不会影响旧案件格式；新增工作台文件独立保留。请勿为了回退界面删除已有工作台记录。
