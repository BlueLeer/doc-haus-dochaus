# 上传处理进度

网页上传使用 `POST /matters/:id/documents?async=true`，文件接收后立即返回
202 和任务 ID。OCR／索引后台执行，网页每秒查询 `/matters/:id/uploads`。
原同步上传接口保留，避免影响其他调用方。

- 提取文字／准备模型：不确定进度条，不显示虚构百分比。
- PDF 转图：已转图页数 / 总页数。
- PaddleOCR：已识别页数 / 总页数，模型初始化期间为 0 页。
- 索引：已写入片段数 / 总片段数。
- 全部结束才显示“处理完成”；失败显示错误并允许重新上传。

百分比是当前阶段百分比，不代表剩余时间或整份文件总体完成度。
DOCX 和已有全文缓存可能跳过转图及 OCR 阶段。
页面切换、刷新后会重新查询任务；临时断网显示重新连接而不是任务失败。
同案件同名文件的重复进行中任务被拒绝。

任务状态目前保存在服务内存，保留有限已完成历史，服务重启不能断点恢复。
未实现 300 页作业的持久化队列、取消和资源限流。

验证：93 项 ingest 测试通过，前后端类型检查与网页构建通过。
独立虚构案件 `matter-7361b4` 验证一页、三页中文扫描上传，后台状态变化、
完成后自动显示文档；浏览器切换至案件工作台再返回可见已完成进度条。
